# Publishing EUI-NEO To Meson WrapDB

[Meson WrapDB](https://github.com/mesonbuild/wrapdb) hosts the wrap files that
let any Meson project consume EUI-NEO with `meson wrap install eui-neo` and
`dependency('eui-neo')`.

Everything needed from this repository is already in place:

| Item | Location |
| --- | --- |
| Meson build | `meson.build`, `meson_options.txt` |
| Dependency wraps | `subprojects/*.wrap` (glfw, freetype2, libpng, sdl2, zlib, curl) |
| Meson helper | `meson/copy_assets.py` |
| Documentation | `docs/meson.md` |
| CI | `.github/workflows/meson.yml` |
| Metadata generator | `packaging/wrapdb/prepare_release.py` |

## Prerequisites

1. **The release tarball must contain the Meson build.** WrapDB does not need a
   patch when the upstream release already ships `meson.build`. So commit the
   Meson files to the repository that hosts releases and cut a tag afterwards.
2. **Version consistency.** The tag (`v0.6.1`), `project(version:)` in
   `meson.build`, and the version requested from the generator must agree;
   WrapDB's sanity checks verify that the version appears in the source URL and
   that `project()` carries a valid SPDX `license`.
3. **Repository.** Upstream is `sudoevolve/EUI-NEO`. Releases published from a
   fork work too, but pointing the wrap at the canonical repository is
   preferred. Pass `--repo` to change it.

## Step 1 - generate the wrap and the metadata

```sh
python packaging/wrapdb/prepare_release.py --version 0.6.1 --write
```

This downloads
`https://github.com/sudoevolve/EUI-NEO/archive/refs/tags/v0.6.1.tar.gz`,
computes its SHA-256, and writes `packaging/wrapdb/eui-neo.wrap`:

```ini
[wrap-file]
directory = EUI-NEO-0.6.1

source_url = https://github.com/sudoevolve/EUI-NEO/archive/refs/tags/v0.6.1.tar.gz
source_filename = EUI-NEO-0.6.1.tar.gz
source_hash = <sha256>

[provide]
dependency_names = eui-neo
```

`dependency_names` must stay `eui-neo`: the project publishes
`meson.override_dependency('eui-neo', eui_neo_dep)`, which is what WrapDB's
`dependency('eui-neo')` assertion resolves against.

## Step 2 - fork and patch WrapDB

```sh
git clone https://github.com/<your-account>/wrapdb
cd wrapdb
git remote add upstream https://github.com/mesonbuild/wrapdb
git checkout -b eui-neo
cp /path/to/EUI-NEO/packaging/wrapdb/eui-neo.wrap subprojects/eui-neo.wrap
```

Add the release to `releases.json` (keys sorted, `eui-neo` goes after `eudev`
style neighbours - `releases.json` is regenerated by the project's tooling, so
keep it alphabetically consistent):

```json
"eui-neo": {
  "versions": ["0.6.1-1"],
  "dependency_names": ["eui-neo"]
}
```

The revision suffix starts at `-1` and only increments for WrapDB-side changes
(a new upstream version gets its own entry, e.g. `0.6.2-1`).

Add the CI configuration to `ci_config.json`:

```json
"eui-neo": {
  "debian_packages": [
    "libx11-dev",
    "libxrandr-dev",
    "libxinerama-dev",
    "libxcursor-dev",
    "libxi-dev",
    "libxkbcommon-dev",
    "libgl1-mesa-dev"
  ],
  "alpine_packages": [
    "libxi-dev",
    "libxkbcommon-dev",
    "mesa-dev"
  ]
}
```

Only X11 and OpenGL are listed, because those cannot come from other wraps;
glfw, freetype, zlib, libpng, and curl are resolved from the wraps bundled in
the release, and WrapDB prefers testing those fallbacks. Node:

- Do **not** add `libcurl4-openssl-dev`/`curl-dev`: curl must resolve through
  its wrap.
- The tray backend is skipped on WrapDB runners because neither glib/gio nor
  GTK3 + libappindicator is installed there; `enable_tray` degrades quietly in
  subproject builds (see `docs/meson.md`). Add `libglib2.0-dev` (Debian) and
  `glib-dev` (Alpine) if you also want the StatusNotifierItem code compiled in
  CI.
- `meson test --suite eui-neo` runs with `build_tests=false` by default, so no
  tests are registered and the step passes. Enable them only together with
  `--buildtype=release`-equivalent options, because several unit tests are
  `assert()`-based.

## Step 3 - validate locally

Quick check of the wrap in isolation (as documented in WrapDB's README):

```sh
meson setup builddir -Dwraps=eui-neo
meson compile -C builddir
```

Full check, the same entry point the pull-request CI uses:

```sh
python3 -m pip install license-expression PyYAML
./tools/sanity_checks.py
```

`tools/sanity_checks.py` configures, compiles, tests, and installs every wrap
with `--fatal-meson-warnings`, so the port must be warning-clean. A build can
also be inspected with `TEST_SKIP_BUILD=1 ./tools/sanity_checks.py` before
running the long compile pass.

## Step 4 - open the pull request

```sh
git add subprojects/eui-neo.wrap releases.json ci_config.json
git commit -m "Add eui-neo 0.6.1"
git push origin eui-neo
```

Open the PR against `mesonbuild/wrapdb`. CI builds the wrap on Ubuntu, Alpine,
macOS, MSYS2, and Visual Studio (x86, x64, arm64) and runs the license check.

## Fallback: releasing without upstream Meson support

If the Meson build cannot reach the released tree yet, the wrap can carry a
patch instead: keep the wrap pointing at the released tarball and add
`patch_directory = eui-neo`, then place `meson.build`, `meson_options.txt`,
`meson/`, and `subprojects/*.wrap` under
`subprojects/packagefiles/eui-neo/`. WrapDB accepts added files but not
overrides of upstream files, and the port should move upstream as soon as a
release contains it.
